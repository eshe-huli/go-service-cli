# greeter: agent contract

This is an ordinary Go service generated by **gsvc 0.1.0**, policy **go-service/v1**.
Use the CLI to change structure. Implement business behavior in developer-owned files.
Do not recreate NestJS mechanisms, build another framework, or invent platform integrations.

## Start every task

```sh
gsvc version --json
gsvc contract --json
gsvc inspect --json
gsvc check --json
```

Inspect the live manifest and ownership map; do not rely on stale examples. This
repository pins the CLI version. A version mismatch is an error, not permission to
edit the pin. If gsvc is unavailable, report the blocker instead of generating a
second architecture by hand.

## Supported structural workflow

```sh
gsvc add module payments --dry-run --json
gsvc add module payments
gsvc add command create-payment --module payments \
  --in 'amount:money,currency:string' --out 'payment_id:string' --dry-run --json
# Apply the same reviewed command without --dry-run. --expect PLAN_ID binds a review.
gsvc add command create-payment --module payments \
  --in 'amount:money,currency:string' --out 'payment_id:string'
gsvc add endpoint create-payment --module payments --path /payments
```

These are examples, not instructions to create a payments module for an unrelated task.
Commands are writes (POST); queries are reads (GET). Input types are string, money,
bool, and int64. Input fields are required. Money remains an exact decimal string;
syntax validation is not currency arithmetic, rounding, or a business invariant.

## Edit boundaries

* `gsvc.json` and `.gsvc/ownership.json`: CLI-managed. Never hand-edit or reset hashes.
* Generated wiring, operation contracts, HTTP bindings, runtime helpers, and these
  instructions: CLI-managed. The checker compares them against canonical output.
* Application operations, dependency structs, business tests, domain behavior,
  module factories, bootstrap wiring, and main: developer-owned.
* Ordinary additional Go files are allowed in established business packages; the
  dependency rules still apply. Add public operations/endpoints through the CLI.

Use `gsvc inspect --json` for exact paths and ownership. Never delete managed files,
add lint suppressions, alter CI to pass, or weaken the policy to solve a feature task.
For explicit field changes, use `gsvc change operation NAME --module MODULE --in
'new_field:string' --dry-run --json` (omit --in or --out to preserve that side).
Review the plan, apply, and update business code/tests to match. Use `gsvc change
endpoint` for a route path change. These commands regenerate contracts, not behavior.
Unsupported adapters or architectural decisions require a reviewed CLI extension.

## Dependencies and execution

Domain code uses permitted standard-library packages only. Application code depends
on its own domain plus the small fault/validation boundary, not HTTP, SQL, the
filesystem, or another business module. Persistence belongs in the postgres adapter;
pgx/v5 is the only approved external application-source import family in this profile.
Do not add another router, ORM, DI container, global service locator, or event bus.

Use context.Context explicitly as the first argument to Execute. Define small
consumer-owned interfaces, inject them in operation-specific dependency structs,
and compose at the module boundary and bootstrap.Wire. Never add init() wiring.

Do not claim success from a placeholder. New operations intentionally return 501
until implemented. Replace pending business tests with real assertions, not skipped
or empty tests. Add success, failure, cancellation, and relevant scope/transaction
checks. Do not copy tenant identity from arbitrary request JSON.

## Definition of done

```sh
gsvc check --verify --strict --json
gsvc check --verify --strict --race --json  # where the race toolchain is available
```

Strict mode rejects scaffold markers and calls to testing skip helpers. Verification
runs real Go tests and vet; it executes project code and is not a sandbox. Inspect
the final diff, preserve existing behavior, and report implemented behavior, tests,
and genuine limitations. Do not state that authorization, persistence, delivery, or
performance is verified when the task did not establish it.

## Scope of this foundation

The generated API is **unauthenticated** and binds to loopback by default. Health
reports process liveness, not dependency readiness. There is no database adapter,
identity client, event delivery, or authorization integration generated in v0.1.
Do not expose a generated service to an untrusted network without adding the required
security/infrastructure work through reviewed extensions.

These rules reduce accidental agent drift. They are not a security boundary against
an agent allowed to modify the policy, checker, and CI. Require checks in CI and review
changes to the CLI, manifest, ownership map, and workflow configuration.
